# 有预算的自适应局部轨迹

本次改动保留未知环境、在线 LiDAR 感知和最终安全网关，在短轨迹规划分支增加确定性的候选生成及有限曲率细化，不引入深度学习或完整地图依赖。

## 使用入口与范围

`configs/trajectory_planner.yaml` 的 `trajectory_planner.adaptive_candidates.enabled` 为 `true` 时，在 `--local-navigation-mode trajectory` 的短轨迹分支生效。已有后台规划进程继续采用最新请求优先，控制循环不等待优化结果。

多机配置中的 `navigation.enabled: true` 会使用 `SwarmFlightBridge` 的栅格路线速度选择。这是另一条运动生成分支，本次没有将其替换为圆弧优化器。运行了多机配置不等于验证了新圆弧分支。B 的编队 YAML、统一 settings、地图文件和最终控制权、点云时效、机间避碰及碰撞门控均未修改。

## 每次规划

1. 根据最新障碍距离选择前瞻长度，生成原有九类基础圆弧和满足条件的回归路线候选。优先检查上一族和直行；历史轨迹不能凭旧证书重放。
2. 先检查固定候选，保留已完成评估的可行结果。候选安全检查覆盖其整个折线路径，包含采样点之间的线段。
3. 由实时目标方向、前方观测障碍的距离梯度，以及上次选中的曲率提出最多四个新曲率。它们仅用于提出候选，不构成安全证明。
4. 在较好的可行前进候选周围，默认最多进行两次曲率细化。所有新路径仍由受限曲率圆弧生成，不任意推动单个路径点。
5. 沿用目标进展、净空、轨迹一致性、未知空间惩罚、左右保持、窄通道和后退恢复等评估/选择机制。自适应曲线复用既有族名称；日志中的 `generation_source` 和实际 `curvature` 可区分固定与新曲线。
6. 使用净空和转弯曲率计算附加速度上限，传入轨迹跟踪器，并在 APF 修正后再次限速。这个上限是保守运动启发式，不等于完整的动力学或制动可达性证明。实际派发仍须经过原有网关。

## 数量与时间上限

默认总上限为十八条，包含基础、回归、自适应和细化候选。自适应曲率限定在原有 `[-0.90, 0.90] 1/m` 范围。配置会检查候选数量、细化次数、采样间隔和前瞻长度的有效范围。

`max_compute_ms: 20.0` 是从本次 `plan()` 开始计时的协作式预算：候选之间、几何检查分块之间、部分评估阶段检查截止时间。Python/操作系统调度和正在进行的一次数组运算不能硬中断，因此不能承诺每次调用绝对小于20毫秒；最终统计同时记录实际耗时和超时次数。地图/距离场构建、IPC、RPC 和控制派发不属于这个预算。

预算耗尽时丢弃正在评估的候选，只从本次已经检查完成的候选中选择。若没有已检查的可行候选，则返回无选中轨迹和零规划指令，交由现有失效/恢复流程处理；不盲目沿用历史计划，也不直接绕过网关飞行。

旧的 `enable_distance_field_refinement` 会逐点推动路径，开启本功能时不执行该旧细化，避免产生未经曲率重新验证的形变。需要传统对照时将 `adaptive_candidates.enabled` 设置为 `false`；未包含新配置的老配置仍采用传统分支。

## 诊断与验证

`TrajectoryPlanResult` 增加 `evaluated_count`、`adaptive_generated`、`refinement_count`、`budget_exhausted`、`fallback_reason` 和 `speed_limit_mps`。工作进程的 `trajectory_adaptive_worker` 日志包含无可行结果；主循环在采用轨迹时记录实际来源、曲率和速度上限。

功能测试覆盖：非预设曲率、障碍变化、历史曲线重生成、候选数量、细化曲率、细障碍线段检查、超时保留已检查候选、无可行候选不重放、速度上限和配置接线。原有网关、碰撞、状态时效及编队测试也需回归。

离线性能复现：

```powershell
python scripts/benchmark_adaptive_trajectories.py --iterations 30 --workers 1 --output runs/adaptive/planner_1.json
python scripts/benchmark_adaptive_trajectories.py --iterations 30 --workers 5 --output runs/adaptive/planner_5.json
```

脚本比较当前版本的固定采样、固定候选加线段检查、以及自适应候选三种模式。固定采样对照也使用本次距离查询加速，不能据此宣称相对完全未改动的旧检出版本的加速倍数。结果记录 P50/P95/P99/最大值、预算耗尽次数、选中候选数量及线段净空复查；源文件哈希按 LF 换行规范化，避免 Windows 检出换行造成误报。

`artifacts/adaptive_trajectories/2026-11-23/` 保存本机一次单进程及五进程结果。它们是静态观测几何上的规划调用，五进程仅模拟并发 CPU 负载，不是五机协同飞行、互避或完整闭环任务验收，也未包含摄像头和 RPC。还需在实际仿真中分别测试新短轨迹分支的单机绕柱、双机、五机，并记录感知年龄、控制频率、网关拒绝原因和全程安全距离。

此次自适应模式的实测结果如下。每个进程、每种场景记录30次调用，另有3次预热；表中取相应场景/进程的最大 P95，不是所有样本混合后的 P95。

| 离线负载 | 普通场景最大 P95 | 8000点场景最大 P95 |
| --- | --- | --- |
| 单进程 | 1.77 ms | 20.29 ms |
| 五进程并发 | 2.14 ms | 20.51 ms |

单进程与五进程共900次自适应调用，选中折线路径对测试障碍点的净空复查未发现违反硬阈值。高点数场景每次都耗尽预算并使用已检查候选，未执行额外细化；因此这些数据不能用于宣称8000点条件下仍能完整评估所有候选，或一定比固定采样更快。
