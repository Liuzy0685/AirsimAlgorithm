# 阶段二：统一状态来源

跨进程发布与订阅约定见 [`多机通信与控制协议.md`](多机通信与控制协议.md)。本模块目前只提供进程内快照，不自动构成跨进程权威状态服务。

`coordination.state_provider.StateProvider` 复用 `sensors.state_reader.StateReader`，通过现有单条 AirSim RPC 连接顺序读取配置中的 1～5 架无人机。`CoordinateTransformer.validate()` 必须先通过；读取结果的位置、速度和姿态按已验证的本机坐标系转换到公共 World NED。角速度仍为机体坐标，遵循 `VehicleState.angular_velocity_body_radps` 字段定义。

## 接口

- `get_snapshot()`：执行一轮采集，返回 `SwarmStateSnapshot`。`timestamp`、`acquired_at` 使用单调时钟秒，`VehicleState.timestamp` 保留 AirSim 纳秒时间戳。
- `get_vehicle_state(name)`、`get_all_vehicle_states()`、`get_neighbor_states(name)`：查询最近一轮快照中仍未过期的状态；不触发额外 RPC。未采集、读取失败或过期时不返回该机状态。
- `is_state_fresh(state)`：按单独采集时间和 `max_age_s` 判断。AirSim 时间戳不前进的状态会拒收。
- `from_adapter(adapter, names, transformer)`：用旧 `StateReader` 构建适配层，保留旧读取入口。

`SwarmStateSnapshot` 有 `sequence_id`、采集结束单调时间 `timestamp`、有效状态 `states`、`collection_complete`、总耗时 `collection_duration`、各机采集时间 `acquired_at`、各机 RPC 耗时 `read_duration_s`、失败原因 `errors`、最大采集时差 `max_time_skew` 和 AirSim 时间戳最大时差 `max_sim_timestamp_skew`。任一时差超过 `max_skew_s` 时整轮状态不供算法使用；单机失败时保留其余有效状态，但 `collection_complete=False`。调用方需要完整邻机集时必须检查此标志。

目前 `automatic_mode.py` 仍使用旧 `StateReader` 和 `collision_predictor.to_common_ned()` 路径；ORCA、priority_hold、APF 和速度派发没有改动。新状态服务是并行对照入口，实际飞行路径切换须等 AirSim 实测验证。

## 实测

在 AirSim 运行且 PythonClient 可导入时，执行：

```powershell
python scripts/validate_swarm_state.py --settings-json <AirSim settings.json> --swarm-config configs/swarm.yaml --samples 10
```

脚本只读，不取得飞行控制权。验证失败会在采集前停止。对五机配置执行同一命令可测每架 RPC 耗时与整轮时间。本机开发环境的 127.0.0.1:41451 未连接 AirSim，因此当前只有假客户端测试结果，不能将其解释为真实坐标误差或 RPC 性能。阶段一 `validate()` 的速度检查只验证旋转数学性质，并没有独立的世界速度传感器对照；姿态也尚未与世界位姿朝向逐机对照。旋转坐标部署前仍需在目标 AirSim 版本做运行验收。
