# 多无人机协同避障选型与本次集成

调研日期：2026-10-30。结论针对本项目的 Python / AirSim 速度指令架构，并非宣称某算法在所有无人机系统中最优。

## 结论

当前阶段采用 **水平 ORCA 速度过滤 + 同向绕行偏置 + 异常停车请求 + 原有 LiDAR 静态避障**。保留 CBMBA 全局引导和局部轨迹规划，只在派发速度前过滤无人机间冲突。后续高速、真正三维密集飞行，应评估 DCAD 类 ORCA + MPC，或带动力学模型的 CBF-QP。

代码原本已接入 `coordination/orca_2d.py`，因此本次不是重新引入一套 ROS 导航框架，而是修复现有求解器及失败处理，补上测试。没有导入或复制第三方项目的源码。

当前 Python 求解器枚举边界交点并逐一检查约束，对 k 个邻居的最坏复杂度约为 O(k³)。它适合当前少量无人机的原型验证；不能把官方 RVO2 在大量代理上的性能直接归到本实现。扩大机群时，应测量求解耗时、RPC 读取耗时，并评估官方 RVO2 求解器和有明确作用范围的邻居检索。

## 候选比较

以下“适配”是结合本项目接口作出的工程判断，非同一平台实测排名。

| 方法 | 能力与条件 | 本项目适配判断 |
|---|---|---|
| CPA + 优先级悬停（现有基线） | 恒速预测、确定唯一让行者；不生成连续绕行速度 | 易接入，但停车不必然能让另一机通过，不能作为失联时高优先级继续前进的依据 |
| RVO / HRVO | 互惠速度障碍；HRVO 针对互相反复改向的振荡 | 速度接口适配，但本项目已有 ORCA，没有明显理由退回这条路线 |
| **ORCA** | 把对端状态转为速度半平面，双方通常各承担一半避让责任；在可行交集内选择接近期望的速度 | **近期首选**，与现有速度派发接口直接匹配。不能把理想瞬时速度模型下的结论当成真实四旋翼保证 |
| BVC / B-UAVC | 在各机安全空间分区内规划；B-UAVC 显式考虑位置/感知不确定性 | 需要把安全区域约束接入轨迹生成，概率版本还需要协方差；目前缺这些接口 |
| CBF-QP | 用安全约束最小化修改原控制器；有加速度约束和四旋翼相关研究 | 适合作为后续安全过滤层，但必须匹配实际控制量、动力学及采样/延迟，不能仅套一个速度公式就声称有严格安全性 |
| **DCAD（ORCA + MPC）** | 基于 ORCA，结合四旋翼平坦性 MPC、下洗区域与状态估计 | 高速四旋翼的优先升级方向；需要建立/辨识模型并解决实时优化及跟踪接口 |
| EGO-Swarm | 面向复杂未知环境的分布式、异步多机轨迹规划；已有完整开源系统 | 更适合整体规划系统升级。项目依赖 ROS/C++ 及轨迹通信，直接接入现有 Windows/Python 管线的改动较大 |

## 发现的问题与修复

1. **ORCA 边界投影错误**：原代码沿边界法向计算候选，而不是沿边界切向投影，可能丢失最接近期望速度的可行解。
2. **速度圆交点错误**：修正边界线至原点的垂足和判别式；线完全位于速度圆外时不产生伪交点。
3. **高优先级失败放行**：以前对端数据过期、无可行解、绕行方向受 LiDAR 阻挡时，高优先级机可能继续原指令。现在 ORCA 模式下所有优先级均返回水平零速度请求，并进入已有高度保持/垂直逃逸处理。`priority_hold` 模式保留为对比基线。
4. **对称相遇停滞**：测试中，无偏置 ORCA 的四机、八机完全对称换位没有在给定时间内全部到达。增加可配置的同向绕行偏置，仅修改期望速度，所有 ORCA 半平面和最大速度限制仍需满足。

偏置不是 HRVO、DCAD 或官方 ORCA 的完整实现，也不是任意场景的无死锁证明。它是本项目的一项小型工程扩展。

```yaml
coordination:
  algorithm: orca
  passing_bias_mps: 0.1  # 默认；0 关闭扩展，恢复无偏置 ORCA
  prediction_horizon_s: 3.0
  safety_distance_m: 2.0
```

本机期望速度 `v_pref` 与某对端在预测窗口内有冲突时，沿 `(-v_y, v_x)` 添加少量偏置（NED XY 中为向右转）。偏置幅值不超过配置值及原期望速度的 20%，最后依然求解完整 ORCA 可行交集。为兼容原有速度上限，配置偏置不能大于该机最大水平速度。

## 验证及其边界

`tests/test_inter_uav_orca.py` 包含 21 项测试：解析几何回归、无解/非有限输入、2/4/8 机对称换位、两种优先级下的失联/过期/无解/静态障碍失败处理、NED 到机体速度转换。

换位测试设置：圆周半径 10 m，目标位于对径，最大速度 1 m/s，安全中心距 2 m，预测 3 s，每步 0.1 s，共 70 s；每步同步计算各机新速度，检查**整个运动线段**中的最小机间距离，避免仅检查采样端点漏掉碰撞。有无偏置共六组场景均通过间距检查；开启偏置的 2/4/8 机均在窗口内到达目标邻域（0.15 m）。这只验证完全同步、瞬时精确速度跟踪的数学模型。

运行：`python -m pytest tests/test_inter_uav_orca.py -q`。全量回归：`python -m pytest tests/ -q`。

本次执行结果：专项 21 项通过；全量运行 1187 项通过、5 项在 `tmp_path` 初始化时因沙箱默认临时目录不可创建而报错。用工作区内新建的 `--basetemp` 目录重跑这 5 项及专项测试，26 项全部通过。没有在 AirSim 内启动飞行，也没有取得真实闭环碰撞率数据。

尚未验证的实用条件：AirSim 闭环跟踪误差、异步读状态、真实通信延迟、最大制动能力、三维相向运动、旋翼下洗、狭窄通道及非合作对端。停止请求不等于瞬间停车，也不能证明已经进入危险间距的两机一定可恢复。静态障碍否决 ORCA 输出后，双方互惠假设可能被打断，仍需闭环场景验证。

`safety_distance_m` 是中心距阈值，应按两机机体包络、定位/跟踪误差、最坏延迟和制动余量设置；当前 2 m 只是已有配置，未经动力学标定，不能当作通用安全值。当前水平约束会保守地避让所有高度的对端，不以高度差豁免；它没有下洗模型。

## AirSim 验收建议

先在空旷场景低速验证双机对向、直角交叉、追越与一机悬停，再测试四机交叉和带障碍绕行。记录实际共同坐标机间最小距离、碰撞事件、到达率、停滞时长、循环延迟和每机求解时间。专门注入对端读取失败与时间戳过期，确认两种优先级都会请求停车。进一步测试中存在初始重叠或无可行速度时，应报告不可行并停止试验，而非将停车回退算作成功避障。

与 `passing_bias_mps: 0`、`algorithm: priority_hold` 在相同初始条件和速度下比较；没有实际 AirSim 结果前，不报告真实飞行碰撞率改善。
