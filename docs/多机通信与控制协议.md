# A/B/C 多机通信与控制协议（v1 草案）

**状态：接口契约已定义，通信服务和飞行控制网关尚未实现。** A 负责人维护本协议；B、C 依据此协议开发并在合并前共同审查。`common/constants.py::PROTOCOL_VERSION` 当前为 `1`。本协议不授予任何进程 AirSim 飞行控制权。

## 1. 现状与边界

代码现状：`scripts/launch_swarm.py` 为每机独立进程；`automatic_mode.py` 内的旧 `StateReader` 读取邻机，ORCA/priority_hold 继续走旧路径。`coordination/state_provider.py` 已有 1～5 机顺序读取、转换、快照和过期检查，但未接入旧控制路径。`common/models.py` 有公共命令和遥测模型。前端 `frontend/src/telemetry.ts` 已接受 `ws://127.0.0.1:8000/ws/telemetry` 风格的 JSON 帧，当前仍可显示演示数据。代码中尚无 A/B/C 跨进程总线、`VehicleCommandGateway` 或真正的命令去重/权限检查。

因此 v1 先约定消息与行为，实施时分别增加服务与端到端测试。任何一方不得把自己单独采集的 AirSim 状态标记为“权威多机快照”。

## 2. 进程拓扑和发布权

第一版采用**仅监听本机回环地址的 WebSocket**。地址与频率由部署配置注入；下列路径为拟定默认值，服务尚未创建。

| 通道 | 生产者 | 消费者 | 拟定默认频率 | 内容 |
| --- | --- | --- | --- | --- |
| `ws://127.0.0.1:8765/ws/swarm` | A 的状态服务 | A 各机控制进程、B、C | 5 Hz，与当前 `swarm.yaml` 的 `peer_poll_interval_s=0.2` 对齐 | 唯一权威 `swarm.snapshot` |
| 同一 A 通道的 `formation.command` 上行 | B | A 的命令接收器 | 最多 5 Hz，变化时可立即发 | `FormationCommand` |
| 同一 A 通道的 `coordination.status` 下行 | A | B、C | 状态变化时立即发，至少 1 Hz 心跳 | 冲突/避障/恢复状态 |
| `ws://127.0.0.1:8000/ws/telemetry` | C 的遥测服务 | 浏览器前端 | 5–10 Hz | 现有前端 `TelemetryFrame` |

A 状态服务负责一次采集、一次坐标校验并发布带 `sequence_id` 的快照；A 每机控制进程订阅其结果。B 只发布编队期望；C 订阅 A 的权威状态并转换成前端格式。C 和浏览器不连接 AirSim RPC。相机数据由 C 单独读取或订阅图像服务，不阻塞 A 的状态/控制循环。B/C 不重采集同一份权威状态。

同一实例的连接握手须声明 `protocol_version`、`role`（`a_controller`/`b_formation`/`c_telemetry`）、`producer_id`、`stream_id`。A 服务按连接身份授权消息类型，**不信任消息体自报的 `source`**。回环地址之外的部署须增加身份认证；在认证实现前禁止开放外部网络。

## 3. 统一消息封装

WebSocket 每帧一个 UTF-8 JSON 对象，最大 2 MB（与现有前端解析上限一致）。内部 A/B/C 帧使用以下封装：

```json
{
  "protocol_version": 1,
  "type": "swarm.snapshot",
  "producer_id": "a-state-service",
  "stream_id": "boot-uuid",
  "sequence_id": 102,
  "sent_at_unix_ms": 1793318400000,
  "payload": {}
}
```

`stream_id` 在发布进程每次重启时更新；同一 `stream_id` 内 `sequence_id` 严格递增。`sent_at_unix_ms` 只用于日志和 C 的展示转换，不参与飞行安全时效判定。未知 `protocol_version`、未知消息类型、字段缺失、非有限数、超过尺寸上限或身份不匹配的帧必须拒绝并记原因。v1 可以忽略**新增的可选展示字段**，不得忽略未知控制字段或降低已有校验。

### `swarm.snapshot`（A 发布）

`payload` 包含 `snapshot_id`、`collection_complete`、`collection_duration_s`、`max_receive_skew_s`、`max_sim_skew_s`、`vehicles`。`vehicles` 是 1～5 个以 `vehicle_name` 为键的对象，必须覆盖配置中的全部车辆。每个对象包含：

| 字段 | 类型和语义 |
| --- | --- |
| `valid`、`validity_reason` | 布尔值与字符串；失效时 `state=null` 且原因非空。`StateProvider.states` 中仅有有效机，`errors` 中为无效原因；序列化时合并两者。 |
| `state.position_ned_m`、`state.linear_velocity_ned_mps` | `[x,y,z]`，公共 World NED，分别为 m、m/s。 |
| `state.orientation_quaternion_xyzw` | `[x,y,z,w]`，机体 **FRD → 公共 World NED** 的主动旋转；实测验证前不得宣称姿态坐标已确认。 |
| `state.angular_velocity_body_radps` | `[wx,wy,wz]`，Body FRD，rad/s；不进行 World NED 旋转。 |
| `state.timestamp` | AirSim 原始仿真时间，ns；每架机独立。 |
| `state.received_monotonic_seconds` | A 服务本机采集时的单调时钟，s，供诊断；订阅者不得拿它与自己的单调时钟直接相减。 |
| `received_at_unix_ms` | C 可展示的接收墙钟，ms，不能用于避障新鲜度判断。 |

快照本身的 `sequence_id` 来自 `SwarmStateSnapshot.sequence_id`。A 在发送前检查转换已验证、状态有效、采集时差和 AirSim 时间戳时差。订阅者在自己进程记录 `received_monotonic_seconds`，按**接收后的本机年龄**和 `snapshot_id/sequence_id` 判断是否可用；断线后不得继续使用缓存作实时避碰输入。

### `formation.command`（B → A）

`payload` 是 `FormationCommand`，包含 `vehicle_name`、`mode`、World NED 目标/速度、`formation_id`、`valid`、`priority` 和必需的 `lifecycle`。`mode=position` 时使用 `target_position_ned_m`，`mode=velocity` 时使用 `desired_velocity_ned_mps`。旧 `timestamp_s` 为兼容字段，**不作为命令有效期**。

`lifecycle` 使用 `common.models.CommandLifecycle`：

```json
{
  "command_id": "uuid",
  "sequence_id": 17,
  "issued_at": 123000000000,
  "expires_at": 123500000000,
  "source": "formation",
  "task_id": "mission-42",
  "stream_id": "b-boot-uuid",
  "ttl_s": 0.4
}
```

`issued_at`、`expires_at` 均为 AirSim 仿真 ns，`expires_at > issued_at`；`ttl_s` 从 **A 接收成功的本机单调时刻**起计。A 只有在仿真时间区间内且接收后年龄小于 `ttl_s` 时才能采用命令。两种时钟独立校验，绝不互相相减。仿真暂停时，单调时钟期限仍阻止旧命令持续执行。`command_id` 全局唯一；同一 B `stream_id + vehicle_name + task_id` 下序号递增，重连不重置，进程重启必须换 `stream_id` 并重新握手。A 对相同 `command_id` 去重，对旧序号拒收；重启后的新流须重新验证身份与任务归属。`lifecycle.sequence_id` 应等于封装层 `sequence_id`。

B 从最近一份有效的 A 快照取得 AirSim 仿真时间来填写 `issued_at`；没有有效快照时暂停发布。A 以自身最新仿真时间校验命令，不能采用 B 或 C 的 Unix/单调时钟替代。

`AvoidanceCommand` 和后续其他控制请求使用相同生命周期；`AvoidanceCommand.source` 是算法来源（如 `orca`），须与 `lifecycle.source` 一致。`FormationCommand` 的 `lifecycle.source` 固定为 `formation`。Python 旧构造方式暂保留以兼容阶段一，但 `require_lifecycle()` 会拒绝其跨进程发送/派发。

### `coordination.status`（A → B/C）

`payload` 包含 `vehicle_name`、`state`、`reason`、`active_command_id`、`snapshot_id`、`task_id`、`sim_timestamp_ns`。状态只能为 `NORMAL`、`CONFLICT_DETECTED`、`AVOIDING`、`CONFLICT_CLEARED`、`FORMATION_RECOVERING`、`EMERGENCY`，代码常量在 `common/constants.py`。A 发布冲突与避障结果；B 仅在 `CONFLICT_CLEARED` 后提出重新集结目标，A 再检查安全性，确认后进入 `FORMATION_RECOVERING`。状态回退或领航机异常均须附原因。

## 4. 断连、重连、超时

心跳 1 Hz；连续 2 秒未收到有效快照/心跳视为失联。客户端以 0.5、1、2、5 秒上限的退避重连；重连后先握手并请求最新完整快照，不回放旧速度命令。A 的命令接收器对 B 断线、快照失效、命令过期或去重拒绝必须返回结构化 `command.ack`（`accepted=false`、`reason`、`command_id`），同时进入本地安全决策。C 前端断线/超过 3 秒无帧显示离线；当前前端还有 10 秒旧帧和 5 秒未来帧校验，C 应保持该现有格式或协同 C 修改前端解析。

失联、ORCA 无可行速度和控制进程异常时，A 的 SafetyFilter/网关按当前障碍、相对速度、可用制动距离和高度选择限速减速、可验证的悬停/保持、避障退出或紧急策略。**悬停不是通用默认动作。** 无可信状态或无可验证安全动作时进入 `EMERGENCY`，禁止继续派发旧速度。具体可行动作需要实测和独立测试后落地。

## 5. 控制权与优先级

每架机仅有一个有效控制者。A 的 `CommandAuthority` 按 `vehicle_name` 管理租约、控制进程身份和续租；租约失效后网关拒绝旧控制者，接管者必须完成显式交接。A 的 `VehicleCommandGateway` 将成为唯一 AirSim **飞行控制**入口，包括 takeoff、hover、land、emergency_stop、moveByVelocityAsync 及其他运动 API；`VelocityArbitrator` 只决定巡航速度，不代替生命周期控制。B 不发 AirSim 控制指令，C 不发运动指令。

安全/紧急 > 避障/恢复 > 编队目标 > 普通导航。ORCA 无解不得把编队速度直接穿透到控制器。`coordination.algorithm=orca` 与 `priority_hold` 是互斥实验模式；同一周期只允许一个机间策略修改最终速度。**当前仓库尚有** `shared_flight_session.py`、`manual_mode.py`、测试脚本及 `velocity_controller.py` 的直接 AirSim 调用；统一网关接线前不能声称单一控制入口已经实现。

## 6. 字段、配置与前端适配

内部 World NED 位置/线速度，四元数 XYZW，Body FRD 角速度，AirSim 时间 ns，本机单调时间 s。前端现有 `TelemetryFrame` 使用 `type=telemetry`、`frame=world_ned`、**Unix ms** `timestamp`、`drones`、`obstacles`；C 将 A 的有效快照转换成这个格式，不能把 AirSim ns 或单调秒直接填入前端 `timestamp`。前端当前要求 `goal`、`status`、`obstacles`；C 必须从真实任务/地图获取或与前端负责人调整可空字段，不得用演示值冒充真实数据。

配置归属：A 管 `swarm.yaml`、计划中的 `swarm_5_drones.yaml` 和 `avoidance.yaml`；B 管 `formation.yaml`；C 管 `telemetry.yaml`、`frontend_config.yaml`。目前速度限制分布在 `trajectory_flight.yaml`、`trajectory_planner.yaml`、`vehicle.yaml`，安全距离和轮询周期在 `swarm.yaml`；新增服务必须从这些实际配置注入，不复制硬编码默认值。A 在接入网关时统一权威参数来源并验证跨文件一致性。拟定的 WS 地址、心跳和超时值也必须进入各方配置后才能上线。
