# A：机间避让、异常退出与运行时队形切换

本轮基于 `2e665d1`。用户已反馈该感知时效修复在 B 的电脑有效；这是用户确认，
与本轮本机新采集的验收证据分别记录。新工作位于 `feature/a-coordination-hardening`。

**五机无 B 规划、同时独立互换终点的强冲突压力场景尚未通过。**
原始失败和未验证清理全部保留；它与现有 B 编队绕柱任务是不同验收项目，不能互相替代。

## 本轮修复的实际问题

### 候选速度与最终网关采用同一邻机假设

原标准 ORCA 候选假设双方各承担 0.5 的避让责任；最终 A 网关则要求候选对邻机的
**实测速度**通过三维 CPA，不能提前相信邻机下一条尚未观测的指令。
在两机相距 5 m、各以 1 m/s 迎面飞行的回归中，旧候选在后一种假设下预测仅剩约 0.95 m，
会被 2 m 最终门槛拒绝。

启用 A 权威服务的控制链现在先生成全责任速度障碍候选（responsibility=1），
在首选单侧半平面无解时，从最多 291 个候选中寻找另一侧/不同速度的 CPA 可行解。
每个返回候选都针对所有邻机实测速度检查；最终网关仍独立执行原三维 CPA 与原始 LiDAR 检查。
备用搜索直接检查非凸速度障碍可行区域，不宣称仍满足原互惠 ORCA 的全部半平面。

规划首选距离为 `2 m + 2 × 本机限速 × 指令时长 + 0.05 m`；
备用候选仍须满足至少 `2.01 m` 的水平预测距离，最终三维安全阈值仍是 **2 m**。
首选余量不能变成当前位置已进入该余量时拒绝一切退出方向的硬边界。
旧独立导航的标准 0.5 ORCA 保持可用。

A 权威状态模式不再用 0.2 s 私有邻机缓存混合新本机状态；每周期读取同一份快照中的各机状态。
最终网关若发现上游候选对最新邻机速度不再满足 CPA，会尝试重新求解并再次经过完整 CPA、
原始三维 LiDAR、时效与控制权检查；修改过的实际速度记录 `gateway_velocity_refined`，
并报告 `AVOIDING`。无解或净空不足时继续拒绝，不把停车当成无需验证的许可。

这是带有有限候选备用搜索的工程实现，不提供真实动力学、加速度、通信不确定性下的安全或收敛证明。
无可行候选时仍须验证停车提议；零速度并非天然安全动作。

### 异常状态和计算期间过期

- `SafetyFilter.check_velocity` 独立检查本机/邻机位置和速度的维度、有限性及非法布尔值。
  NaN 不能再因比较结果为 false 而漏过 CPA。
- 邻机接收年龄为负或 NaN 时停车提议进入原网关校验。
- 原始点云变换和净空计算完成后，再检查状态连接、原快照期限、扫描期限、B permit 与控制锁。
  计算耗时不会延长运动指令的授权。
- `GatewayFlightClient` 在安全回调返回之后、实际 RPC 之前再次核验控制租约；
  回调期间被撤销或到期的租约不能继续派发。
- 无法验证安全清理时仍保留 `MANUAL_INTERVENTION_REQUIRED`；本轮没有新增绕过感知的强制降落路径。
- 降落未确认、解锁失败或 API 释放失败，现在均明确进入人工介入状态；不会仅停留在 LANDING、
  同时错误显示 `manual_intervention_required=false`。共享起飞入口拒绝接管已启用的旧 API 控制，
  拒绝时不解锁、不释放别人的控制权，也不重放任务。

二维网格协同模式禁用旧单机垂直脱困：邻机回波不能再触发未经编队高度设计的爬升。
原始高度误差保护不放宽，旧独立单机模式的垂直避障保持原配置。

全队启动器现在先对全部车辆执行只读 API 占用、地面静止、原始 LiDAR 起飞柱状通道检查，
任何成员不合格都不会启动控制进程；各机在解锁前再次检查可见起飞通道。
Corridor 旧起点的实测近墙距离约 0.83 m，小于 0.9 m，已新增回归确保提前拒绝。
检查排除机体下方地面，保留侧墙和路径高度内的原始近回波；没有观测到点不代表不可见空间已认证。

### “B 已采用”与“实际已收敛”分开

`GET /api/v1/missions/{id}` 新增 `formation_convergence`：

```json
{
  "physical_settled": false,
  "reason": "verifying_dwell",
  "revision": 2,
  "tracking_error_m": {"Drone2": 0.12},
  "dwell_s": 0.6,
  "distinct_frames": 4
}
```

A 自己用权威位置到 B 目标的误差、跟随机相对领航机速度计算，不能直接相信 B 报告的零误差。
要求当前任务 RUNNING、配置版本一致、完整机群、名义队形、时间匹配，且权威状态与 B 反馈均在 0.6 s 内。
误差使用配置的 `recovery_tolerance_m`，相对速度不超过 0.2 m/s；至少 3 个不同快照、持续 1 s。
重复查询/重复快照不能增加证据帧；超时、临时纵队、版本或流变化会重新验证。
这是前端显示依据，不是运动许可，也不代替最终控制网关。

领航机任务完成增加独立的稳定观察窗口：默认 `formation_settle_duration_s=2.0`、
`formation_settle_frames=3`，只统计新权威快照。进入容差的一瞬间不再立即结束全队任务。
时长可设置 1～10 s，帧数至少 3。

## 独立航线专项测试模式

`navigation.independent_goals: true` 必须同时启用网格导航并关闭 `adaptive_slots`。
每架飞机跟踪自己在 settings 出生原点下的 `goal_x / goal_y / target_z`，
不能同时启动 B 编队服务，不允许 Actor 相对原点。
该模式保留同一个 A 权威快照、控制锁、ORCA/CPA、LiDAR 网关和起降清理路径；
全队均到达各自目标并低速稳定后，才允许任务完成。
前端编队任务 API 拒绝使用这种配置，避免误把独立目标当作 B 槽位。

目标被停着的邻机占据时，先规划到保持距离的临时接近点，邻机开始运动后恢复原终点。
直线接近点被第三架停机占据时，从 6 个有界方向中选择满足全部临时邻机与已观测障碍余量的侧向点，
并在仍安全时保持所选点，避免每帧换边。原终点与完成判定始终不变。
选择侧向接近点后保持到达，再回到原终点；邻机刚开始移动不再立即解除该路线，避免过早回并。

生成器把相遇航线放在 maze 柱体区域西侧的独立空地，验证机间相遇，
不能将其称为狭窄通道或绕柱性能验收。各架次使用全新的 UE 实例和独立日志。

```powershell
python scripts/build_encounter_configs.py --output runs/encounter_profiles
python scripts/validate_inter_uav_encounters.py --output runs/ideal_encounters.json

# 全部串行实测；已有 RPC/A/API 服务时拒绝启动。
python scripts/run_coordination_suite.py --ue-editor "UE4Editor.exe的绝对路径" --blocks-project "Blocks.uproject的绝对路径" --output runs/coordination_suite_新目录 --extend-test-floor --confirm-simulation-clearance
```

默认套件包含：真实 API `line → vee → line`、双机迎面/交叉/追越、现有 B 五机编队绕柱、Corridor 地图会车，
以及 B 服务主动断开与一个控制进程协同退出。后两项通过现有 stop 文件结束对应进程，
不是 OS 强杀或突然断电测试；验收要求全队实际落地、解锁并释放 API。
清理无法确认时套件停止，保留仿真实例和日志，不自动重置或开始下一架次。
独立五机互换终点的压力反例单独用 `--cases five_way` 运行，不计入已通过项目。

`--extend-test-floor` 只给独立相遇场景增加临时地面，不修改地图资产或墙/柱体。
实例启动后、任何 A/B 控制进程启动前，测量其真实渲染网格并调整为 60×60×0.5 m；
用一架未解锁、API 未占用的飞机在扩展区做设置阶段的落地探测，再恢复全部飞机的出生点并重新确认稳定。
探测与恢复、地面范围写入 `fixture_setup.json`；场景附加物也写入飞行环境元数据。
有附加地面的相遇结果明确标记为测试设施条件，不能冒充原始地图地面覆盖验证。
队形切换、B 五机编队、两项退出与最终 Corridor 试验使用原地图地面。

前端联调范围：本轮用 HTTP 验证器代替 C 页面发起真实请求，验证的是接口 → B → A 的实飞链路。
本分支没有 C 的页面代码，尚未验证浏览器按钮、视频和地图交互；C 可直接接入上述新增收敛字段。

单独运行的入口仍为 `run_swarm_acceptance.py`；新增 `--fault b_disconnect` 或
`--fault controller_stop`，在全部进入巡航后注入。故障验收使用单独
`fault_acceptance_passed`，不会把提前协同停止记为飞行任务完成。
