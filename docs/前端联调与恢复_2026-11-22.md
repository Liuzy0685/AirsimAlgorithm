## FlyingExampleMap 双机启动示例

在同一个算法提交下执行。UE 使用本机 UE 4.27.2；工程、SDK、Python 路径按实际位置修改。

```powershell
$repo=(Get-Location).Path
$py='C:\path\to\python.exe'
$ue='D:\UE_4.27\Engine\Binaries\Win64\UE4Editor.exe'
$project='D:\team\Blocks\Blocks.uproject'
$settings=Join-Path $repo 'configs\acceptance\settings_2.json'
$engineLog=Join-Path $repo 'runs\flying_2\engine.log'
New-Item -ItemType Directory -Force (Split-Path $engineLog) | Out-Null
$env:AIRSIM_PYTHONCLIENT_PATH='D:\team\AirSim\PythonClient'

# 先启动明确的地图和同一份 settings，等待 RPC 就绪。
& $ue $project '/Game/FlyingCPP/Maps/FlyingExampleMap' '-game' "-settings=$settings" "-abslog=$engineLog" '-windowed'

# 另一个终端，工作目录仍是同一份算法仓库。
& $py scripts/operator_api.py --profile flying_2 --blocks-project $project `
  --engine-log $engineLog --runtime-dir runs/operator_flying_2 `
  --allow-origin http://127.0.0.1:8000 --allow-flight
& $py -m telemetry.server

# 再一个终端；默认仅按需采集，不预先启动十路视频。
& $py scripts/camera_service.py --vehicles Drone1 Drone2 --interval 1
```

五机时换成 `flying_5`、`settings_5.json`，相机服务指定 `Drone1 Drone2 Drone3 Drone4 Drone5`；
地图清单可复用同一未修改的工程。实际飞机数、名称、原点仍由 UE 与 settings 决定。
网页继续显示 `actual_start`，`supports.spawn_edit=false`：本轮没有开放飞行前瞬移或自由出生点编辑。
终点使用公共 World NED，巡航 Z 由后端能力返回；跟随机终点仍由 B/A 计算。

第一视角使用各机相机 `0`；第三视角使用外部相机 `{vehicle}Third`。
1/5/10/20 FPS 是请求采集上限，不是十路并发下的实际帧率保证；高帧率应先做地面负载测试。

## 地面接触预检

共享地面名称识别补充 `Ground_5/Ground_6`，不做宽泛 `Ground*` 放行。
原有落地状态、静止速度、接触法线、穿透深度、碰撞时间戳与启动后新事件检查继续执行。
正常启动不接管残留 API 控制权；恢复接管必须使用下述显式接口。

## 失败任务恢复降落

`POST /api/v1/missions/{mission_id}/recovery-land`

```json
{"request_id":"new-recovery-operation-id","expected_revision":2}
```

需要与普通任务相同的操作令牌、允许的 Origin，以及服务器 `--allow-flight`。
只接受 `FAILED/INTERRUPTED + manual_intervention_required`；另一个任务或恢复在运行、
旧监督进程尚在、版本不符时拒绝。接受返回 HTTP 202 与 `completed=false`，不是落地成功。
同一请求重试复用 ID，新一次恢复使用新的 ID 和当前 revision。

恢复由独立 A 子进程执行：

1. 先取得全机群 OS 控制锁；任一锁占用时，所有飞机都不发送控制命令。旧状态服务仍在也拒绝。
2. 校验同一地图、settings、公共坐标、新鲜且前进的状态和机间下降列间距；横向运动过快或
   已有墙体接触时拒绝。不会强杀原控制者，不会重新起飞、解锁电机或发送 XY 位移命令。
3. 通过原 `VehicleCommandGateway` 的租约、最终控制权和锁检查，逐机请求降落。
   新碰撞仍检查；异常时尝试经网关取消降落任务，保留人工处理状态，不在空中解除控制。
4. 需要多个不同仿真时间戳的稳定落地观测，随后确认解锁返回值和实际 API 释放状态。
   旧 SDK 若先报告地面接触、后更新落地标志，只有具备该任务原 A 预检地面高度记录时，
   才允许以一致高度、向上法线、≤2cm 穿透、≤0.05m/s 速度、≥2秒和≥5帧稳定接触
   作为独立落地证据。报告保留 SDK 落地值与实际使用的确认来源；旧任务缺记录时不猜测。
5. `GET /operations/{request_id}` 查询结果；任务中的 `recovery.vehicle_results` 返回各机
   `landing_confirmed/disarmed/api_control_released/cleanup.control_released`。
   全部确认才清除人工处理标记并进入 STOPPED；任何缺失仍为 FAILED/INTERRUPTED。

原始失败结果保留在 `original_failure`；原文件不覆盖。API 重启不重放降落命令。
`POST /api/v1/recovery/check` 仍是只读检查，用于已安全落地并释放控制权后的确认，不代替降落请求。

前端增加独立恢复按钮、各机清理结果和刷新后的恢复操作查询；普通停止按钮不绕过失败状态门控。
恢复降落执行期间，普通停止操作会被明确拒绝，继续等待同一个恢复操作的结果，不伪造另一个停止成功。
本轮浏览器访问授权未获准，不能声称新增页面按钮已完成真实浏览器复验。
