三轮都沿用同一双机 maze、settings_2.json、formation_2.yaml、速度和安全阈值，全部策略开启且几何模式为 swept，无额外前端相机流。均记录零碰撞，确认实际落地、解除武装及 API 释放后退出 UE。前两轮与第三轮的诊断触发逻辑不同，不作为性能配对或速度提升证据。

第三轮两份真实快照分别是领航机网格路线（124个静态点）与跟随机直线路线（148个静态点）。它们是正常路线基线，不能当作失败现场。离线回放的路径可用性、目标阻挡判定、路线原因与航点均与记录一致，关键源码哈希匹配。`.replay.json` 中 `geometry_matches` 的布尔值表示判定是否一致，不是当时路径/目标的状态；实际状态看 `recorded_outcome` 和 `replay`。

`synthetic/` 是另外生成的离线夹具，明确标为 synthetic_fixture：起点膨胀格占据、临时队友占据终点，以及 CPU 搜索预算耗尽。前两者复现原几何判定；CPU 预算夹具在冻结时间回放时可以找到路，刻意验证该工具不会声称复现真实调度超时。这些夹具不是 AirSim 故障的复现。

本轮相关回归与 CLI 测试共208项通过；不是一次新的项目全量回归。后台写入阻塞/失败、队列与条数上限、临时障碍保留、采集副本独立、重规划时刻、源码缺失/伪造等均有覆盖。异步和限量不等于零资源开销，最终安全网关继续检查原有截止时间。

原来第三组 swept 的180秒超时没有在这三轮中重现，根因仍未确认。旧失败证据保留于 [失败说明](../../live_navigation_ab/2026-11-23-repeated-maze/FAILURE.md)，不能用这三次成功覆盖它。下一次出现停滞时，优先取 `persistent_no_route` 文件，检查起点格、障碍记忆、瞬时队友障碍与逃逸拒绝原因，离线复现后再改行为。默认策略和模式不变，暂不扩大五机或相机负载。

标准启动命令已经携带 --log-file，无需 B 修改 YAML 或 C 修改状态协议；新文件写在日志旁的 navigation_traces/。回放命令见 docs/local_navigation_hardening.md。原始快照和派生回放分别保存，SHA256 清单用于核验原始文件；archived_export.py 仅保存当时的归档流程和本机路径，不能在 artifacts 目录直接启动飞行。
