## 可得出的结论

- 修复前全开策略在180秒时限内未完成任务；原始失败证据一并保留。
- 修复了平滑器将速度跟踪误差反复计入限幅、导致持续降速的问题；修复后全开策略完成任务，但本轮飞行时间较基线增加约23.5%，不能称为性能提升。
- 关闭 smoothing 后，本轮时间接近基线；该开关同时关闭新增平滑与延迟限速。此结果只提示继续拆分和调试这个组合，不能证明其余策略普遍更好。
- 三组通过试验均记录零碰撞，最小机间距离超过配置的2米；它们不是所有场景下安全性的证明。
- 新策略仍默认关闭。未把降低速度上限、放宽点云时效或关闭碰撞门控作为解决办法。

## 证据与限制

raw_summary.json 保留原始汇总；summary.json、trajectory.csv、navigation.jsonl 和 trajectory.png 由既有导出脚本生成。图中叉号仅表示柱体中心，不是完整障碍轮廓。
comparison.json 核对了匹配轮的地图、settings、编队、非试验参数及完整 Python 源码清单一致性。ablation.json 是探索性追加轮，不能替代多次随机化对照。
全程控制频率和感知年龄汇总取自 realtime_architecture_summary；滑动窗口 P95 最大值另列，不作为全程 P95。轻量导航中的旧 hover/trajectory 来源计数不能当成物理悬停次数。
这是单机本地电脑上的双机无额外相机 pilot；没有覆盖五机、相机负载、狭窄通道会车、全部地图或另一台电脑。继续这些试验前应先定位全开组合的耗时退步。
归档 helper 用于核对原运行流程，包含本机路径；复现需复制到 runs/<新目录>/run_live_ab.py、配置本机 SDK/UE 路径，并使用新的输出目录。不要直接在 artifacts 中启动它。
